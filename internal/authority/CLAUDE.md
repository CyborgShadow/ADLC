# internal/authority

The decision layer. Nothing else in the module decides where work goes.

- `states.go` — the lifecycle states, the proposers, the requirements, and `Table()`: the complete
  transition authority. **Everything not on the table is refused.**
- `authority.go` — `Decide`, which answers one proposal, and the `check` for each requirement.
- `advance.go` — `NextState`, the pure function that computes what the control plane will attempt
  next; plus `CapabilityFor`, `PickedUp` and the stage mapping a person reads.
- `facts.go` — `Gather`, which reads the ledger so the rules do not have to.
- `roadmap.go` — the planning pipeline: segment states, `NextSegmentState`, progress rollups.
- `generation.go` — `AdmitItem`, the shape rules for work an agent proposes into existence.

## What goes wrong here

**A rule that runs its own query.** `Decide` is a pure function of `Request` and `Facts`, and that
is not tidiness. A rule that reads the ledger cannot be tested without a database, and rules that
are expensive to test are rules nobody writes a negative case for. If a new requirement needs a
fact, add a field to `Facts` and populate it in `Gather`.

**Adding a state in one place.** A state is `AllStates()`, an entry on `Table()`, a `NextState`
case, a `CapabilityFor` priority, a `PickedUp` pair where it is a waiting state, and a `StageOf`
mapping. The blocked/resume escape hatches are generated by looping over `AllStates()` precisely so
a new state cannot quietly lose them — but nothing generates the rest. The tests walk the table and
will name the half you missed.

**Letting a verdict name a state.** `NextState` takes a capability and one of `pass`, `fail`,
`reject`, `blocked`. If a change makes the next state depend on anything an agent wrote free-form,
replay stops working and the whole re-derivability property goes with it.

**Ordering the checks by convenience.** `Decide` answers identity questions first — does this edge
exist, may this proposer propose it, is the item actually in the state the proposal claims. A run
working from a stale read must be told that, not told its evidence is thin.

**Widening the fork after arbitration.** `afterArbitration` is where the pipeline stops before
touching something real. An unknown radius stalls rather than applying, and that is deliberate: the
one thing this policy exists to prevent is an unattended apply.

## Tests

`authority_test.go` pins the refusals: a non-existent edge, a stale read, a verifier that is also
the author, a criterion passed on inspection alone, an uncommitted tree, a gate that could not run,
an approval for a different plan, an expired approval, two approvers for a region, an unknown
radius, the attempt limit. `advance_test.go` pins the arithmetic: the same inputs always give the
same answer, every stage refuses the wrong role, nothing an agent reports clears an approval or a
merge, every dispatchable state has an edge out, and every state maps onto a stage a person reads.

Both files also carry whole-table properties — every edge names a proposer, every edge is
well-formed. Those are what catch a half-added state.
